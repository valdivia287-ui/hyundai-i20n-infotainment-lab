# Hyundai i20 N infotainment lab — 30 October 2026

> This is a **public progress summary of Codex (GPT-6 Sol Alto)'s reports and screenshots provided by the owner**. It is not an independent audit of the private VM, code patches or recorded captures. Do not publish OEM artifacts or raw private traces.

## Milestone: original Home navigation between pages

**Reported outcome:** a controlled test in a fresh disposable QEMU overlay caused the original Hyundai `AppHomeScreen` to move **from page 0 to page 1** following a drag generated via a laboratory IVI input-controller build.

Three cross-checks were described by Codex:
- The original client log reported `advancedModePageChange(1)`.
- The original QML emitted `onFlickStarted` (and `onMovingChanged: true`).
- A capture reportedly displayed page 1, containing additional application icons.

This establishes a **bounded interactive page navigation** in the reported test; it does **not** yet demonstrate a fully working multimedia application suite, production touch navigation, or application launches.

## How the blocker was isolated (reported chronological findings)

1. The prior guest input device captured touch gestures, yet the OEM client did not receive `wl_touch`.
2. A lab-made IVI seat/focus utility started requesting both pointer (**2**) and touch (**4**) focus; the seat association had already been accepted.
3. The gesture was intercepted by the Weston reference UI's surface (`wl_surface@42`, IVI **2001**) rather than OEM Home's IVI surface **0**. The reference surface also triggered `workspace_control`.
4. Merely hiding the reference surface did not resolve its presence in the layer's input order. An experiment removed or shut down the **reference interface process only** inside the disposable guest, leaving the compositor running.
5. Weston then recorded `wl_touch.down/motion/up` directed toward a Home-associated surface, but no corresponding events initially appeared in the OEM client. With a further **30-second delay**, `AppHomeScreen` itself recorded `wl_touch.down`, motions and `up`.
6. The touch gesture reached the original application, but did not cause QML `ListView` movement (`onMovingChanged` absent).
7. A pointer drag then reached Home as `wl_pointer.button` + motion, but coordinate values were implausibly small (~5.58–1.64 for hundreds of visible pixels). An isolated **laboratory IVI input controller compiled from publicly available COVESA code** was tested against the original controller as baseline. Attribution/license of any actual code incorporated must be audited before redistribution.
8. The laboratory controller corrected the reported pointer coordinates (~1430 to ~422), and the original QML emitted `onMovingChanged: true` and `onFlickStarted` with distance about **840**.
9. A final delayed capture and client log were reported to confirm a page **0 → 1** transition (`advancedModePageChange(1)`). Codex reported the test VM was shut down and its logs preserved.

## Follow-up: original ApplicationManager launch dependency (Codex, GPT-6 Astra Medio)

After the successful Home page-navigation tests carried out with **GPT-6 Sol Alto**, the owner switched Codex to **GPT-6 Astra (medium reasoning)**. In a reported session lasting **1 min 57 s**, Astra inspected the latest icon-click trace and documented:

- The original `AppHomeScreen` **receives and processes the N Mode icon press**.
- Its request identifies **`appid=500`**.
- The lab environment lacks the running/registered D-Bus service **`com.lge.hyundai.avn.appmanager`** required to handle that application launch.
- Therefore, **N Mode has *not* opened**; this is a downstream application-manager dependency, not proof the click itself failed.
- Codex reported **8 successful tests** and **281 verified hashes**, along with a **clean VM shutdown** and preserved disposable overlays/logs.
- Codex said it **prepared a configuration option to try the original Hyundai ApplicationManager**, but **had not run that experiment in QEMU** at the time of the screenshot.
