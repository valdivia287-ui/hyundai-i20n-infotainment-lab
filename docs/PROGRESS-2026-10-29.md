# Hyundai i20 N infotainment lab — 29 October 2026

> Public, evidence-limited progress note based on Codex's text reports and screenshots provided by the project owner. Private logs, guest overlays and source diffs have not been independently inspected here. The latest interrupted experiment is **not** confirmed successful.

## Established baseline (reported)

- QEMU + Weston/Wayland IVI + original Qt 5.4.1 run `AppHomeScreen` in a disposable Linux guest.
- Controlled fullscreen Home captures reported visible at 110 and 170 seconds, with 929,959 changed pixels versus Weston reference. An earlier disappearance corresponded to the test's 125-second timeout.
- BC3 variant enum = `23`. In a test-only overlay, switching `vehicleVariant` 5 → 23 persisted to SQLite and revealed a third page indicator, **not** necessarily a navigable page.
- Home created SQLite schema; 47 D-Bus call types were catalogued from outgoing headers. Missing localization and supporting services remain.

## IVI input investigation timeline

1. Original `ivi-input-controller.so` found in the OEM rootfs, SHA and dependencies checked by Codex, and loaded in the guest; initial gestures were not delivered to the client.
2. An original `ivi_input` v1 interface was examined. A laboratory helper was built to associate the `default` input seat with Home IVI surface **0**. Attempt 1 happened before the surface existed; attempt 2 was acknowledged as `CA_IVI_INPUT_ACCEPTED attempt=2 surface=0 seat=default` / `ivi_input.input_acceptance(0, "default", 1)`.
3. The client later recorded **`wl_pointer.enter`**, but reportedly lost focus immediately after a pointer movement; no drag or QML `ListView` index change was confirmed.
4. Codex investigated a claimed ~256× pointer-coordinate mismatch. Wayland uses `wl_fixed_t` 24.8 fixed-point values; verify raw versus converted units before claiming a scaling fault.
5. QEMU 8.2.2 virtual touchscreen `QEMU Virtio MultiTouch` became visible in the guest. A synthetic swipe was captured by the **guest kernel/input device** with start, intermediate positions and end, but did **not** result in `wl_touch` events in original `AppHomeScreen`.
6. Codex identified a missing **`BTN_TOUCH`** event in the injection sequence and associated the virtual touch device with QEMU's display. An early injection failed inside QEMU in a `qemu-fixed-text-console.device` path; this was not evidence of an OEM crash.
7. Codex changed the VM launcher's virtual-device order to keep the emulated tablet receiving mouse clicks and the touch device bound to its display. The next controlled experiment started, with the IVI seat reportedly accepted again. **At the time of the last owner-shared report, the experiment was still underway when usage credits ran out.** No screenshot or trace confirms `wl_touch` reached Home or changed pages.
